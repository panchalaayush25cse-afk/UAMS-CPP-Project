1. Introduction & Objectives

The University Academic & Record Management System (UAMS) is a console-based C++ application designed and developed as a semester project for the subject Object Oriented Concepts with UML (CE0316). The system simulates real-world university operations including student academic record management, faculty profile handling, teaching assistant role resolution, fee and salary account processing, and persistent binary file storage.

1.1 Project Objectives

  1. To demonstrate practical application of all four OOP pillars: Abstraction, Encapsulation, Inheritance, and Polymorphism.
  2. To implement and resolve the Diamond Problem in hybrid/multiple inheritance using C++ Virtual Base Classes.
  3. To showcase all three forms of data type conversion: Basic-to-Class, Class-to-Basic, and Class-to-Class.
  4. To demonstrate comprehensive operator overloading including unary, binary, relational, and stream operators.
  5. To implement runtime polymorphism through pure virtual functions, abstract base classes, and dynamic binding via base-class pointers.
  6. To persist and retrieve structured data using binary file I/O with random-access file pointer manipulation (seekg, seekp, tellg).
  7. To apply generic programming via C++ function templates and class templates.
  8. To model the system using UML diagrams: Class, Use Case, Activity, Sequence, and State diagrams.

5.2 Diamond Problem Resolution (Virtual Base Class)

In hybrid inheritance, when TeachingAssistant inherits from both Student and Faculty, which themselves both inherit from Person, the compiler would normally create two separate copies of the Person sub-object. This leads to ambiguity when accessing id, name, or email.

Solution: Both Student and Faculty use virtual public Person, ensuring only a single shared Person instance exists within TeachingAssistant. The most-derived class (TeachingAssistant) directly calls the Person constructor in its initialization list. 

class Student : virtual public Person { ... };
class Faculty : virtual public Person { ... };
class TeachingAssistant : public Student, public Faculty {
    TeachingAssistant(...)
        : Person(id, name, email),   // Direct call to virtual base
          Student(...),
          Faculty(...)
    { }
};

B. Three Types of Data Conversion:

  1. Basic to Class: Single-argument constructor CurrencyINR(double amount) converts a primitive double to a CurrencyINR object.
  2. Class to Basic: Casting operator operator double() const converts a CurrencyINR object back to a double.
  3. Class to Class: Conversion constructor CurrencyUSD(const CurrencyINR&) converts INR to USD; casting operator operator CurrencyINR() const converts USD back to INR.

6.2 Three-Way Data Type Conversion

class CurrencyINR {
    int rupees, paise;
public:
    // 1. Basic to Class Conversion
    CurrencyINR(double totalAmount) {
        rupees = static_cast<int>(totalAmount);
        paise = static_cast<int>(std::round((totalAmount - rupees) * 100));
    }
    // 2. Class to Basic Conversion
    operator double() const {
        return rupees + (paise / 100.0);
    }
};

class CurrencyUSD {
    double dollars;
public:
    // 3a. Class-to-Class: INR → USD
    CurrencyUSD(const CurrencyINR& inr) {
        dollars = (inr.getRupees() + inr.getPaise()/100.0) / 83.0;
    }
    // 3b. Class-to-Class: USD → INR
    operator CurrencyINR() const {
        return CurrencyINR(dollars * 83.0);
    }
};

6.3 Binary File Random Access (seekp/seekg/tellg)

bool updateStudentPercentage(int targetId, double newPercentage) {
    std::fstream file(filename.c_str(), std::ios::in | std::ios::out | std::ios::binary);
    StudentBinaryRecord rec;
    while (file.read(reinterpret_cast<char*>(&rec), sizeof(rec))) {
        if (rec.id == targetId) {
            rec.percentage = newPercentage;
            std::streamoff recordSize = sizeof(StudentBinaryRecord);
            file.seekp(-recordSize, std::ios::cur);  // Move back
            file.write(reinterpret_cast<const char*>(&rec), sizeof(rec));
            return true;
        }
    }
    return false;
}

9. Conclusion

The University Academic & Record Management System (UAMS) successfully demonstrates the practical application of all Object Oriented Programming concepts prescribed in the CE0316 syllabus. Through the design and implementation of this system, the following learning outcomes have been achieved:

  1. Deep understanding of OOP pillars — Abstraction (through abstract base classes), Encapsulation (through access specifiers and data hiding), Inheritance (four types including diamond resolution), and Polymorphism (both compile-time and runtime).
  2. Practical C++ proficiency — Including namespaces, templates, operator overloading, friend functions, static members, inline functions, and all forms of type conversion.
  3. File persistence skills — Binary file I/O with random-access capabilities using seekg(), seekp(), and tellg() for efficient in-place record updates without rewriting entire files.
  4. Software modeling with UML — System design documented through Class, Use Case, Activity, Sequence, and State diagrams providing both structural and behavioral views of the system.

The menu-driven interface makes it easy for evaluators to test each concept independently or run all demonstrations sequentially using Option 8, providing a comprehensive viva showcase.
